# eSports Manager — Game Design Document

## Game Flow

### Main Menu

- User starts the game, and can choose to:
  - **Start a new game**
  - **Load game**
  - **Change game settings**
  - **Exit the program**

### New Game

- Once user starts a new game, they can create their manager (define name, nickname, birthdate, nationality).
- On the same page, they can select which eSport they want to play:
  - MOBA: League of Legends-inspired
  - RTS: StarCraft-inspired
  - FPS: Counter Strike-inspired
- Then, the user is taken to another screen. Here is how they define what data he wants to use:
  - The game may generate a new random database in SQLite, which will be their game session. This database can be generated by using .json configuration files. These files have a defined schema to define the database:
    - `teams.json`: Data about teams, including their rosters, players, etc. If players do not provide rosters, the database will generate random players.
    - `tournaments.json`: Data about regions and tournaments. There can be regional tournaments, national tournaments, international tournaments, that can be `premier`, `major`, `minor`, etc. We can define teams that will play in the tournament.
    - `player_names.json`: A list of names and surnames that can be used to generate random names for players. The names are grouped by nationalities.
    - `player_nicknames.json`: A list of nicknames that can be used to generate random nicknames for players.
    - `team_names.json`: A list of team names that can be used to generate random teams.
    - `champions.json`: A list of champions that can be used to generate random champions (MOBA eSports).
    - `races.json`: A list of races that can be used to generate random races (RTS eSports).

    By default, the game will ship with a set of pre-generated data depending on the type of eSports they choose, and the generated database will be generated from these definition files.

  - The game will ship with a pre-generated database, that we are going to tune ourselves. So the user can use this database in case they don't want to generate a new one. If the player deletes this database, the game will generate a new one.
  - The user can choose to use their own database. This database has to be validated before it can be used by the game. If the database is invalid, the user is prompted about data corruption, and can have the option to choose a new one or generate a random one.
- Each new game session is a SQLite database. If the user chooses a default database, the game will copy the default database and remove any session-related data from it.
- The user can save their game at any time. The database should not save data automatically. So to keep the game running, the changes have to be kept in memory or in a temporary file.
- Once the game selects the database, he is presented with information about the regions and teams.
  - Teams have a reputation level, based on their performance and player overall.
- Once the user selects a team, he can confirm the selection by clicking a Continue button.
- The user is taken to the main dashboard.

### Load Game

- The game provides a list of saved games found in the saves folder.
- Saved games are SQLite databases.
- Saves folder can be managed in the game settings.
- The game can keep a list of saved games in a json file, with a checksum validation to validate the integrity of the save file, to prevent that the game needs to validate to present the list of saved games.
- If a save file is selected, the save file has to be validated. If fails the validation, an error message is presented -> data is corrupted.
- Otherwise, user session is constructed, and user is taken to the game.

## Gameplay

### Main Dashboard

- As most manager games, there is a main dashboard for managing the team.
  - The home dashboard must provide critical and information about the team, next matches, calendar, practices and useful information that the user will have to deal with.
- The dashboard has specific sections for user to administer.
- The gameplay is in "turns": User takes actions, and these actions will have consequences in the next turns.
- User can finish their turn by pressing a "Continue" button on the top right side, on the header.

### Matches

- When user has an incoming match, user will receive messages from their staff with information about the opponent team, and practices and focuses of their own team for the next match.
- User will get assistance to select players, and recommended roster configuration and tactics.
- If the match is the next turn, the "Continue" button becomes "Play Match". The Play match button can have an optional arrow pointing down button that can be clicked and present user with options:
  - **Delegate to assistant coach**: user will not see the match in realtime. Instead, all the draft phase and decisions will be taken by the assistant coach (AI). The user will just see the end result of the match. This is the "instantaneous" match simulation.
  - **Draft and then delegate**: user will draft the team, and then delegate the match to the assistant coach (AI). The user not see the match in real time. Just the end result.
  - **Spectate**: user will see the match in real-time, but will not take part in draft.
  - **Participate (default)**: the complete experience. User participates in draft, and will see the match in real time, and make tactical decisions during the match.
- When a user selects one of the options, they change the state of the "Play Match" button.
  - The user must click the button to play the match according to their desired option.
  - When a user clicks the button, there is a confirmation modal to confirm the action to play the match according to their desired option.

### Scrims

- User can be approached by other teams to schedule scrims, depending on user's team reputation. User can accept or refuse.
- User can approach other teams for scrims. The team might refuse or accept, depending on the user's team reputation.
- Before each scrim, the user can basically do everything that he would do for a normal match: watch, delegate, spectate, participate.
- The state of the "Play Match" button changes to "Play scrim".
- User can have at least one scrim per day. No more than 4 scrims can be played in a single day.

### Solo Queue / Ladder

- Players in the roster can have the option of playing only solo queue/ladder for the day, instead of a rest day or scrim. Solo queue is less tiring than scrims, but provides less experience and less champion pool rewards.

### Practice & Tactics

- User can choose practice focus areas, tactics, and define default roster.

### News & Inbox

- User can read latest news of what happens in the overall game (other leagues, championships, teams, news about the patch).
- User has an inbox to receive messages from players, staff, the directors of the team, and the press.
  - Some messages are only informative, for user acknowledgement.
  - Some messages are requests for action, for user to respond.
  - Some messages are urgent actions that the player cannot end their turn until they have taken care of it.

### Transfers & Scouting

- User can search for players and approach players for a purchase, loan, or show interest.
- User can scout players and find out more about player attributes and traits.
- User can see other teams and their rosters, but can't manage teams that he is not associated with.
- User can be associated with only one team at a time.
- User can list his own players for transfer, approach them for contract renewals, or for breaching contract.
- Staff can assist the user in these tasks.

### Staff

- User can choose their staff. Staff members can influence scouting, player satisfaction, and transfer outcomes.
- Staff can help in several roles, like assistant coach, positional coach, psychological assistant, etc.
- Staff can be hired, fired, and their roles can be changed.
- Positional coaches and psychological assistants can be assigned to specific players, or to the team as a whole.
- Positional coaches can have primary roles that they are good at improving. Once paired with players with the same primary role, they can give a higher boost.

### Finances & Sponsors

- User must be constrained by the team's finances.
- User must select sponsor at the beginning of the season/split.

### Reputation & Satisfaction

- User has a "Satisfaction" meter, that includes several key points that they are going to be judged by the board of directors and the fans of the organization.
- User has reputation with the fans as well.
- User must meet board of directors criteria to remain with the team.
- User gains reputation as they win matches and championship. Reputation gains are proportional to the importance of the matches and championships they win. They lose reputation following the same criteria.
- If user loses their job, they can be approached by other teams, according to the user's reputation.

### Views

- User can view a paginated list of teams in the game, search, filter.
- User can view a paginated list of players in the game, search, filter.
- User can view a paginated list of tournaments in the game, search, filter.
- User can view a paginated list of champions/races in the game, search, filter.
- User can view information about the current meta in the game, recent patch information, and meta changes.
- User can view potential prospects from the Solo Queue/Ladder to approach for a contract.

## Players

- Players in this game have specific attributes that influence the match simulation. Attribute values are in categories: Mental, Physical, Technical (depends on each eSport). Attribute values vary from 0-100.
- Player satisfaction determines how satisfied they are with the current team, manager and staff.
  - Amount of games played influences this metric. Experienced players that are fit to play will get unhappy very fast if they are not selected to play. Unexperienced players or not so talented players will have different reactions.
  - Player satisfaction can be influenced by the user's actions, such as training, player talk, inbox messages, etc.
- Stamina:
  - Players have stamina bars that depletes with practice. If they have higher physical endurance, their stamina will take longer to deplete.
  - If players have very low stamina, their performance in the match will tank.
  - User must balance the team's stamina to prevent players from getting too tired.
  - Stamina affects player morale and satisfaction.
- Player morale is a metric that determines how motivated the player is to play. It is influenced by the user's actions, such as training, player talk, inbox messages, etc.
- Losing games can also lower player morale and satisfaction.
- Players have traits and abilities that differentiate them from others.
- Players have specific roles that they can perform in the game. They have a primary role, and they can have more than one secondary role (MOBA: Top, Jungle, Mid, Bottom, Support).
- Player confidence:
  - Confidence is a metric that kicks in when the team wins many matches in a row, including in practice.
  - Different players have different thresholds to get confidence.
  - Players that perform well in practice can get hyped in the game.
  - Players with good confidence can perform better in the match.
  - A loss can end the player streak, and decrease player morale.
- Players have a champion pool (MOBA):
  - Each champion in the player's champion pool has a mastery tier: Bronze, Silver, Gold, Diamond, Master, Challenger.
  - The higher the mastery tier, the better the player is at the champion, offering boosts to the player's performance.
  - Player champion pools can be increased by playing scrims, or training in Solo Queue. (Scrims increase more than solo queue)
- Players can present demands to the user, such as salary, contract length, etc.
- Players have contracts.
- Players can have a career history.

## Champions (MOBA)

- Champions are eSport-related objects that can influence the outcome of a match.
- Champions have skill values that can increase or decrease, according to the player's mastery level, and the current game patch.
- Meta games can influence the power of a champion.
- Champions have certain roles that can be played. They have one primary role, and can have more than one secondary roles.
- Champions can be banned in the draft, and not be allowed to be selected.
- The game must contain a database of at least 120 champions.

---

## Draft (MOBA)

- Drafting stage is the process that the user has to go through to choose the roster that will play the match, choose their positions, and participate on the drafting phase.
- Before drafting, the user has to define the players that are going to be playing the match and assign their roles.
- Drafting is composed of Banning and Picking phases.
- Usually, for MOBAs, both sides start banning champions (5 or 3 each, depending on the current rules of the tournament).
- Bans are done in a selected timer, in turns.
- The user can choose a champion to ban temporarily, and the choice is only confirmed if the timer runs out or if the player hits Confirm.
- Once confirmed, the AI will choose their champion to ban. The AI will also have a timer, but the user cannot influence their decision.
- If the player is not participating in the match, two AIs will be drafting against each other. Player will not have the power to influence draft, but he can accelerate the time to make it run faster.
- After banning, both sides start picking champions:
  - 5 champion bans: after banning 3 champions each side, the first side (usually the blue side) picks one champion. Then the other side picks two champions. The first side picks two champions. The other side picks one champion. The ban phase starts again, where both teams ban 2 more champions, taking turns. The pick phase restarts. The other side picks one more champion. The first side then picks the final two champions. And the other side than picks its remaining champion.
  - 3 champion bans: after banning all three champions in turns, the pick phase starts. The first side (usually the blue side) picks one champion. Then the other side picks two champions. The first side picks two champions. The other side picks two champions. The first side picks the last two champions and then the other side picks the last champion.
- Drafting can be done in Scrims and Matches.
- When the user is involved in drafting, the user can choose which champions to ban or pick. There is a timer on the user's decision. If they don't make a decision in time, the AI will make the decision for them.
- The user can also choose to let the AI draft for them.
- When it's not the user's turn, the AI will also have a timer, and can make decisions during this entire time (the time it takes for AI to choose may vary).
- User can choose a champion, and it will appear as a temporary choice, but he must confirm the choice to lock the choice.
- AI can also choose a champion temporarily, and switch to other champions later, while there is still time in their draft.
- Once champions are picked, they are associated temporarily with each player in the roster that is playing the match. The user can switch champions during a timer. After the timer is done, or when the user clicks the "Confirm" button, the choice is locked.
- The AI can also choose champions out of order, and switch them later instantaneously. Once the user clicks the "Confirm", if the AI has not yet performed their switch, they will do, and the match will commence.

## Match Simulation

- Text-based match simulation.
- Should produce accurate results for farming, kills, assistances, objectives done, etc.
- Event-based simulation, similar to a Monte Carlo simulation, with conditions. (Taking towers can only happen after 10 minutes passed, you can only take the inhibitor if all the towers from the same lane are down, and you can only take the nexus if at least one inhibitor is down and has not yet respawned and if both tower turrets are down).
- Teams will have "gold". Gold is the advantage that one team has over another. Teams get gold for kills, assistances, objectives, farming, etc. Some objectives are more valuable than others. Farming is not worth a lot of gold.
- The more gold a team has, the more likely they are to make the next decisions and get a favorable outcome in the end.
- Teams can make mistakes, and give advantages away. It depends on player mental attributes and other factors in the game.
- Champions and champion pools can influence the current player ability in the current game.
- Match series:
  - Usually the user will play series of matches, depending on the format of the current championship.
  - Series can be best of two, best of three, best of five, best of seven, etc.
  - If not a series, it's a single match.
  - After each match, the user can see the match results, and talk to their players to affect their motivation or make changes to their roster.
  - Before each match start, the player has to go through the drafting stage. Depending on the tournament rules, they can be "Fearless Draft", which means that the previous picked champions for both teams are automatically banned for the next games in the series. This does not affect the number of bans in the current match. Only picked champions will be unavailable for the current match.
- Matches can be reproduceable, deterministic with the same RNG.
- They can be replayable by feeding the RNG.

## Transfers

- At the off-season, the user can participate in the transfer window.
- The transfer window is a time where the user can buy players from other teams, or sell players to other teams.
- The transfer window is usually two weeks long.

- Global game clock.
- Matchdays.
- Scrimming days.
- Transfer window.
- Weekly staff reports.
